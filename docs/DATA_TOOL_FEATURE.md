# 다음걸음 — 데이터 → 툴 → 기능

> 목표: 노인·장애 당사자와 보호자가 **의미 있는 정보를 쉽고 빠르게** 얻어 실제 문제를 해결하도록 돕는다. 수익·경쟁은 고려하지 않는다.
> 진입로: 당사자 / 보호자 두 가지 모두. 첫 지역: 화성시(경기도 데이터 우선).
> 원칙: "어디 있나"보다 **"다음에 뭘 하면 되나"**를 준다. 공식 창구(읍면동 돌봄팀 등)를 대체하지 않고 **그곳으로 이어 준다**. 진단 결과는 [`DIAGNOSIS.md`](DIAGNOSIS.md).
> 데이터 목록: [`registry/datasets.csv`](../registry/datasets.csv) (작성 2026-10-21, 아이디어 뱅크 관련 API 425종 + 지자체 109종에서 추림)

## 0. 구조

```
[데이터]  원천 API·파일  ──가공──▶  가공 데이터(우리 것)
                                        │
[툴]      가공 데이터를 조회·표시하는 작은 단위 (화면 컴포넌트 + 함수/API)
                                        │
[기능]    툴을 조합해 하나의 실제 문제를 푸는 흐름
```

- **바텀업**: 데이터를 모아 툴을 만들고, 툴을 조합해 기능을 발견한다.
- **탑다운**: 이미 보이는 기능(아래 기능 목록)은 먼저 등록하고, 필요한 툴·데이터를 매칭해 빈칸을 찾는다.
- 툴은 화면 부품이면서 동시에 함수로 노출한다. 나중에 MCP 도구로 열면 AI 상담 흐름에서도 같은 툴을 쓸 수 있다.

## 1. 데이터

### 1-1. 원천 데이터 4계층

| 계층 | 답하는 질문 | 핵심 원천 (P0) |
|---|---|---|
| **제도** | 무엇을 받을 수 있나 | 중앙부처복지서비스 API(D01), 지자체복지서비스 API(D02) |
| **기관** | 어디서 받나 | 장기요양기관 검색·상세(D10·D11), 치매센터 표준(D14), 노인맞춤돌봄 수행기관(D17), 활동지원기관(D30), 사회서비스 제공기관 검색(D31), 발달재활 제공기관(D32), 장애인복지관(D33), 장애인주간보호(D35) |
| **이동** | 어떻게 가나 | 교통약자이동지원센터 표준(D60) |
| **통계** | 우리 동네 사정은 | 경기 읍면동별 등록장애인(D70), SGIS 소지역 인구(D74) |

확인된 점:
- **제도 정보도 API로 나온다.** 한국사회보장정보원의 중앙부처·지자체 복지서비스 API가 지원대상·선정기준·신청방법을 제공한다(실시간). 처음부터 큐레이션할 필요는 없고, **정리·쉬운 글·지역 창구 연결**에 사람 손이 들어간다.
- **장기요양기관 API(건보공단)와 치매센터 표준데이터는 아이디어 뱅크 주제 분류에서 빠져 있었다.** 노인 쪽 핵심이라 직접 추가했다.
- **읍면동 단위 등록장애인 통계는 경기데이터드림에만 있다** (공공데이터포털에 없음).
- 같은 기관이 여러 데이터에 중복 등장한다 (예: 요양원이 장기요양기관·노인복지시설·노인의료복지시설에 모두 있음).

### 1-2. 가공 데이터 (우리가 만들어 낼 것)

| ID | 가공 데이터 | 만드는 법 | 원천 |
|---|---|---|---|
| P1 | **통합 기관 목록** | 공통 스키마(이름·유형·대상·제공 서비스·주소·좌표·전화·출처·기준일)로 합치고 중복 제거 | 기관 계층 전체 |
| P2 | **제도 카드** | 복지서비스 API를 대상(노인/장애/보호자)·소득기준 유무·신청처 유형으로 태깅. 쉬운 글 요약 + 원문 링크 + 기준일 | D01–D04 |
| P3 | **제도 ↔ 기관 유형 매핑표** | "이 제도는 어떤 기관에서 받나"를 사람이 정리 (예: 방문요양 → 재가 장기요양기관 중 급여종류=방문요양) | P1·P2 + 수작업 |
| P4 | **상황 → 제도 규칙** | 질문 답(누가·무엇이 어려운가·등급/등록 여부)을 제도 카드로 잇는 규칙 | P2 + 수작업 |
| P5 | **기관 접근성 프로필** | 기관 주변 역 엘리베이터, 관할 이동지원센터, 건물 편의시설 매칭 | P1 + D60·D63·D65 |
| P6 | **동네 돌봄 지표** | 읍면동별 대상 인구 대비 기관 수·거리 | P1 + D70·D74 |

P3·P4가 이 서비스의 핵심 자산이다. API에는 없고, 현장 지식으로만 만들 수 있다.

### 1-3. API로 안 나오는 것 (직접 채울 빈칸)

- 화성시에서 실제로 신청하는 창구·전화번호·준비물
- 제도 간 전환 규칙 (장애인 활동지원 → 65세 이후 장기요양)
- 정원·대기·이용료 (기관에 따라 다름 → "전화로 확인할 것" 체크리스트로 대신)

## 2. 툴

| ID | 툴 | 보여 주는 것 | 쓰는 데이터 |
|---|---|---|---|
| T1 | 기관 찾기 | 지도+목록, 필터(대상·유형·제공 서비스·거리) | P1 |
| T2 | 기관 카드 | 연락처, 제공 서비스, 평가 결과, 접근성, 기준일 | P1·P5·D12 |
| T3 | 제도 찾기 | 조건·키워드로 제도 목록 | P2 |
| T4 | 제도 카드 | 쉬운 글 요약, 대상, 신청처, 원문 링크, 받을 수 있는 기관(→T1) | P2·P3 |
| T5 | 이동 도우미 | 우리 시군 이동지원센터 연락처·이용 기준, 근처 역 엘리베이터 | D60·D63 |
| T6 | 상황 질문지 | 3~5개 질문 → 해당 제도 카드 묶음 | P4 |
| T7 | 동네 현황 | 읍면동별 돌봄 지표 | P6 |

공통 원칙: 큰 글씨·쉬운 글·스크린리더 대응, 모든 카드에 출처와 기준일, 적은 단계 수.

핵심은 F0·F1·F4다. 나머지는 이들을 받치는 디렉토리 성격이라 뒤로 둔다.

| ID | 기능 | 누가 | 툴 조합 | 빈칸 |
|---|---|---|---|---|
| F0 | **퇴원 후 집에서 돌봐야 할 때** — 이번 주 할 일 → 전화할 곳 → 물어볼 것 → 다음 단계 (첫 시나리오) | 보호자, 병원 의료사회복지사·읍면동 돌봄팀이 건네는 용도 | T6 → T4 → T1·T2, 마지막은 화성시 읍면동 돌봄팀 연결 | 화성시 통합돌봄 실제 절차·창구 |

## 4. 첫 단계

0. **검증 먼저**: F0 시나리오를 종이 한 장(또는 정적 페이지)으로 만들어 보호자 3~5명, 현장 사회복지사 1~2명에게 보여 준다. 질문은 하나 — "이걸 받았으면 덜 헤맸을까?"
1. **데이터**: P0 원천 수집기 → P1(화성시) · P2(노인·장애 태그 붙은 제도만). 화성시 통합돌봄 절차·창구는 직접 정리
2. **툴**: T1·T2·T3·T4 (조회 화면이 먼저 있어야 데이터 품질이 보인다)
3. **기능**: F0 — 보호자 진입로부터, 결과 끝은 항상 공식 창구 연결
